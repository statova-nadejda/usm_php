## Отчет по лабораторной работе по объектно-ориентированному программированию на PHP

### Задача 

Реализовать систему управления банковскими транзакциями с использованием ООП-подхода в PHP. Поддерживается хранение, добавление, удаление, поиск, сортировка транзакций, выполнение вычислений над коллекцией и вывод данных в виде HTML-таблицы.

### Структура работы

```
php_lab05/
├── index.php                    # Основной файл запуска
├── Transaction.php              # Класс одной транзакции
├── TransactionRepository.php    # Хранение коллекции транзакций
├── TransactionManager.php       # Бизнес-логика
└── TransactionTableRenderer.php # HTML-рендеринг таблицы
```

### Шаг 1. Создание класса `Transaction`
Хранит данные одной транзакции. Все свойства приватные, доступ только через геттеры.

| Свойство      | Тип        | Описание                  |
|---------------|------------|---------------------------|
| `$id`         | `int`      | Уникальный идентификатор  |
| `$date`       | `DateTime` | Дата транзакции           |
| `$amount`     | `float`    | Сумма                     |
| `$description`| `string`   | Описание                  |
| `$merchant`   | `string`   | Получатель                |

**Методы:**
- `getId()`, `getDate()`, `getAmount()`, `getDescription()`, `getMerchant()` — геттеры
- `getDaysSinceTransaction(): int` — количество дней с момента транзакции

### Шаг 2. Создание класса `TransactionRepository`
Управляет коллекцией транзакций.

| Метод                            | Описание                              |
|----------------------------------|---------------------------------------|
| `addTransaction(Transaction)`    | Добавить транзакцию в коллекцию       |
| `removeTransactionById(int)`     | Удалить транзакцию по ID              |
| `findById(int): ?Transaction`    | Найти транзакцию по ID                |
| `getTransactions(): array`       | Получить все транзакции               |


### Шаг 3. Создание класса `TransactionManager`
Реализует бизнес-логику. Получает `TransactionRepository` через конструктор (внедрение зависимости).

| Метод                                              | Описание                                      |
|----------------------------------------------------|-----------------------------------------------|
| `calculateTotalAmount(): float`                    | Общая сумма всех транзакций                   |
| `calculateTotalAmountByDateRange(string, string)`  | Сумма транзакций за период дат                |
| `countTransactionsByMerchant(string): int`         | Количество транзакций по получателю           |
| `sortTransactionsByDate(): array`                  | Сортировка по дате (по возрастанию)           |
| `sortTransactionsByAmountDesc(): array`            | Сортировка по сумме (по убыванию)             |


### Шаг 4. Создание класса `TransactionTableRenderer`
Формирует HTML-таблицу на основе массива транзакций. Объявлен как `final`.

| Метод                            | Описание                              |
|----------------------------------|---------------------------------------|
| `render(array): string`          | Возвращает HTML-строку с таблицей     |

Столбцы таблицы: ID, Дата, Сумма, Описание, Получатель, Кол-во дней с момента транзакции.

### Шаг 5. Создание интерфейса `TransactionStorageInterface`

Для того чтобы сделать архитектуру более гибкой, создадим интерфейс. И чтобы не было привязки к конкретному объекту `TransactionManager` будет принимать не готовый класс с репозиторием, а интерфейс.

Класс репозитория реализует интерфейс: 

```php
class TransactionRepository implements TransactionStorageInterface
```
И теперь в классе мы передаем не конкретный класс, а абстракцию:

```php
public function __construct(private readonly TransactionStorageInterface $repository){}
```

### Контрольные вопросы

**1. Зачем нужна строгая типизация в PHP и как она помогает при разработке?**

Строгая типизация в PHP нужна для того, чтобы контролировать типы данных, которые передаются в функции и возвращаются из них. При включении строгой типизации PHP перестаёт автоматически приводить типы, например строку к числу, и требует точного соответствия объявленным типам. Это помогает находить ошибки на раннем этапе, делает код более предсказуемым и уменьшает вероятность неожиданных багов, особенно в больших проектах.


**Что такое класс в объектно-ориентированном программировании и какие основные компоненты класса вы знаете?**

Класс в объектно-ориентированном программировании - это шаблон или модель, по которой создаются объекты. Он объединяет данные и поведение. Основные компоненты класса - это свойства (переменные, которые хранят состояние объекта), методы (функции, которые описывают поведение), конструктор (специальный метод для инициализации объекта) и модификаторы доступа (public, private, protected), которые управляют доступом к данным.

**Объясните, что такое полиморфизм и как он может быть реализован в PHP.**

Полиморфизм - это способность работать с объектами через общий интерфейс, не зная их конкретной реализации. В PHP он реализуется через наследование и интерфейсы. Например, если несколько классов реализуют один и тот же интерфейс, их можно использовать взаимозаменяемо. В контексте лабораторной работы это проявляется в том, что класс TransactionManager работает не с конкретным классом репозитория, а с интерфейсом, и ему не важно, какая именно реализация будет передана.

**Что такое интерфейс в PHP и как он отличается от абстрактного класса?**

Интерфейс в PHP - это контракт, который определяет набор методов, которые класс обязан реализовать. В интерфейсе нет реализации методов, только их сигнатуры. В отличие от абстрактного класса, интерфейс не может содержать состояние (свойства с данными) и не может реализовывать логику (за исключением некоторых современных возможностей), а класс может реализовывать сразу несколько интерфейсов, но наследоваться только от одного класса. Абстрактный класс, в свою очередь, может содержать как абстрактные, так и обычные методы с реализацией и хранить состояние.

**Какие преимущества дает использование интерфейсов при проектировании архитектуры приложения? Объясните на примере данной лабораторной работы.**

Использование интерфейсов при проектировании архитектуры даёт гибкость и слабую связанность между компонентами. Это означает, что части программы не зависят от конкретных реализаций, а работают через общий контракт. В данной лабораторной работе это видно на примере TransactionManager, который принимает в конструктор интерфейс хранилища транзакций. Благодаря этому можно легко заменить, например, реализацию, которая хранит данные в массиве, на реализацию, работающую с базой данных, не изменяя сам TransactionManager. Это упрощает расширение системы, тестирование и поддержку кода.
